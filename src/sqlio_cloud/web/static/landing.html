Decision-Support Workload

The analytical benchmark that stress-tests your query optimizer, not just your storage layer.

In the original SQLCAT labs, decision-support testing was how we separated database tiers that could handle real analytics from those that could not. Raw IOPS only tells half the story -- a database that reads pages quickly can still collapse under a 12-table join with hash aggregation and spill-to-tempdb. Data Bench's decision-support benchmark reproduces that pressure using 16 purpose-built analytical queries against a realistic star schema.

The schema models a retail analytics warehouse: a central fact table of line items surrounded by dimension tables for customers, suppliers, parts, dates, nations, and regions. Each query exercises a different optimizer code path -- from simple filtered aggregations that should run in milliseconds, to complex multi-join fan-outs with correlated subqueries, window functions, EXISTS/NOT EXISTS predicates, and CASE-driven conditional aggregation that force the engine to choose between nested loops, hash joins, merge joins, and sort-based grouping strategies.

▒

Star-Schema Dataset

A fact table with foreign keys into customers, suppliers, parts, dates, nations, and regions. Automatically generated at connect time with realistic cardinalities and data distributions.

⚙

16 Analytical Queries

Multi-table joins, grouped aggregations, correlated subqueries, window functions (RANK, ROW_NUMBER), EXISTS/NOT EXISTS filters, CASE expressions, and set operations (UNION, EXCEPT). Each query targets a distinct optimizer decision point.

⏱

Cold vs. Warm Execution

Every query runs twice -- once cold (no cached plan, no warm buffer pool) and once warm. The delta reveals how much your tier benefits from plan caching and data residency in memory.

⚗

Power Score & Geometric Mean

Individual query timings are rolled up into a geometric mean (so no single fast query masks a slow one) and a power score for apples-to-apples comparison across database tiers, SKUs, and cloud providers.

What the queries test

Q1-Q3 — Filtered aggregations, date-range scans, GROUP BY with HAVING
Q4-Q6 — Multi-table inner joins, supplier/part lookups, SUM/AVG/COUNT
Q7-Q9 — Correlated subqueries, EXISTS/NOT EXISTS, nation-to-region fan-outs
Q10-Q12 — Window functions (RANK, ROW_NUMBER), TOP-N per group
Q13-Q14 — CASE-driven conditional aggregation, derived tables, self-joins
Q15-Q16 — Set operations, UNION/EXCEPT, cross-database comparison patterns

How It Works

1

Provision a Test Server

Spin up a dedicated database on the cloud tier you want to evaluate. Any SKU, any provider. Data Bench needs a blank database and a SQL login -- nothing else.

2

Connect

Enter your host, port, credentials, and database engine. Data Bench validates the connection, detects the server version, and confirms connectivity before any tests run.

3

Choose Your Benchmark

Pick a preset -- Smoke (5-15 min), Standard (20-60 min), or Full Stress (60+ min) -- or customize individual tests and block sizes. The preset is a starting point; toggle any test on or off.

4

Run

Data Bench executes each test with live progress streaming. Watch operation counts tick up in real time. No agents are installed on your database -- everything runs through standard SQL over the network.

5

Analyze and Export

Interactive results with latency histograms, thread-scaling charts, and per-metric tooltips written for database engineers. Download a PDF report, CSV for spreadsheet comparison, or JSON for programmatic analysis.
